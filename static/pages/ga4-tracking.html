// 01 — Instalación

GA4 Asíncrono y Diferido

⚡
El Reto: gtag.js es un script de terceros pesado (~50KB). Cargarlo de forma bloqueante retrasa el FCP y penaliza Core Web Vitals, lo que distorsiona las métricas de velocidad que queremos medir.

La solución usa strategy="afterInteractive" en Next.js y defer + carga condicional en Vite, garantizando que gtag solo se ejecuta después del primer pintado.

Next.js 14 (App Router)
Vite + React
app/layout.tsx
import { Metadata } from 'next'
import { GoogleAnalytics } from '@next/third-parties/google'

// ✅ Usa el paquete oficial de Next.js para GA4.
// Internamente aplica strategy="afterInteractive" y gestiona
// el script con Partytown si está configurado.

export const metadata: Metadata = {
  title: 'FiscalAI — Automatización Contable',
}

const GA_ID = process.env.NEXT_PUBLIC_GA_ID as string

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="es">
      <body>
        {children}

        {/* Solo carga en producción para no contaminar datos */}
        {process.env.NODE_ENV === 'production' && (
          <GoogleAnalytics gaId={GA_ID} />
        )}
      </body>
    </html>
  )
}

src/components/Analytics.tsx
import { useEffect } from 'react'

declare global {
  interface Window {
    dataLayer: unknown[]
    gtag: (command: string, target: unknown, params?: Record<string, unknown>) => void
  }
}

const GA_ID = import.meta.env.VITE_GA_ID as string

export function Analytics() {
  useEffect(() => {
    // Solo en producción
    if (import.meta.env.MODE !== 'production' || !GA_ID) {
      console.info('[Analytics] desactivado fuera de producción')
      return
    }

    // Inyecta gtag.js de forma asíncrona y diferida (no bloquea FCP)
    const script1 = document.createElement('script')
    script1.async = true
    script1.defer = true
    script1.src = `https://www.googletagmanager.com/gtag/js?id=${GA_ID}`
    document.head.appendChild(script1)

    // Inicializa dataLayer y configura GA4
    const script2 = document.createElement('script')
    script2.innerHTML = `
      window.dataLayer = window.dataLayer || [];
      function gtag(){dataLayer.push(arguments);}
      gtag('js', new Date());
      gtag('config', '${GA_ID}', {
        send_page_view: true,
        cookie_flags: 'SameSite=None;Secure',
      });
    `
    document.head.appendChild(script2)
  }, [])

  return null // Componente sin render
}

// 02 — Utilidades

analytics.ts — Funciones Tipadas

🎯
El Reto: Sin un archivo centralizado, los eventos quedan dispersos, mal nombrados o con parámetros inconsistentes. Un solo typo en el nombre de un evento rompe todo el funnel silenciosamente.

Un módulo central con tipos estrictos garantiza que cada evento llegue a GA4 con el nombre correcto, los parámetros adecuados y sin duplicados.

src/lib/analytics.ts
/**
 * FiscalAI — Analytics Utilities
 * Wrapper tipado sobre gtag para tracking del embudo de conversión.
 *
 * Uso:
 *   import { trackCTAClick } from '@/lib/analytics'
 *   trackCTAClick({ location: 'hero', label: 'Probar Gratis' })
 */

// ── Tipos base ─────────────────────────────────────────────────────────

type GtagFn = (
  command: 'event' | 'config' | 'js' | 'set',
  eventName: string | Date,
  params?: Record<string, unknown>
) => void

declare const window: { gtag?: GtagFn } & Window

/**
 * Helper interno — envía el evento solo si gtag está disponible.
 * Loguea en desarrollo para debugging sin contaminar GA4.
 */
function send(name: string, params: Record<string, unknown> = {}): void {
  if (typeof window === 'undefined') return // SSR guard

  if (process.env.NODE_ENV !== 'production') {
    console.debug(`[GA4 Event] ${name}`, params)
    return // No envía en dev/staging
  }

  window.gtag?.('event', name, params)
}

// ── 1. CTA Click ────────────────────────────────────────────────────────

export interface CTAClickParams {
  /** Dónde está el CTA: 'hero' | 'navbar' | 'pricing' | 'footer' */
  location: 'hero' | 'navbar' | 'pricing' | 'footer' | 'banner'
  /** Texto visible del botón */
  label: string
  /** Plan al que apunta, si aplica */
  plan?: 'free' | 'pyme_pro' | 'enterprise'
}

/**
 * Disparar cuando el usuario hace clic en cualquier CTA
 * que lleva hacia el acceso a la plataforma.
 *
 * @example
 *   trackCTAClick({ location: 'hero', label: 'Probar FiscalAI Gratis' })
 */
export function trackCTAClick(params: CTAClickParams): void {
  send('cta_click', {
    event_category: 'engagement',
    event_label: params.label,
    cta_location: params.location,
    plan: params.plan ?? 'none',
    value: 1,
  })
}

// ── 2. Scanner / OCR Engagement ─────────────────────────────────────────

export type ScannerAction =
  | 'upload_start'      // Usuario abre el uploader
  | 'file_selected'     // Archivo seleccionado
  | 'scan_initiated'    // Clic en "Escanear"
  | 'scan_complete'     // OCR completado con éxito
  | 'result_viewed'     // Usuario vio el resultado
  | 'result_copied'     // Copió el resultado
  | 'scan_error'        // Error en procesamiento

export interface ScannerEngagementParams {
  action: ScannerAction
  /** Tipo de archivo: 'pdf' | 'image' | 'xml' */
  file_type?: 'pdf' | 'image' | 'xml'
  /** Tiempo de procesamiento en ms */
  processing_time_ms?: number
  /** Confianza del OCR (0-100) */
  ocr_confidence?: number
}

/**
 * Medir engagement con el componente interactivo de escaneo.
 * Mapea cada micro-interacción del funnel interno del scanner.
 *
 * @example
 *   trackScannerEngagement({ action: 'scan_complete', file_type: 'pdf', processing_time_ms: 4200 })
 */
export function trackScannerEngagement(params: ScannerEngagementParams): void {
  send('scanner_engagement', {
    event_category: 'ocr_scanner',
    scanner_action: params.action,
    file_type: params.file_type ?? 'unknown',
    processing_time_ms: params.processing_time_ms ?? 0,
    ocr_confidence: params.ocr_confidence ?? 0,
  })
}

// ── 3. Form Validation Errors ────────────────────────────────────────────

export interface FormErrorParams {
  /** ID del formulario: 'hero_lead' | 'demo_request' | 'signup' */
  form_id: 'hero_lead' | 'demo_request' | 'signup' | string
  /** Campo que falló la validación */
  field_name: string
  /** Tipo de error */
  error_type: 'required' | 'invalid_format' | 'server_error' | string
  /** Mensaje de error mostrado al usuario */
  error_message?: string
}

/**
 * Disparar en cada error de validación de formulario.
 * Permite identificar en qué campo los usuarios se bloquean.
 *
 * @example
 *   trackFormError({ form_id: 'hero_lead', field_name: 'email', error_type: 'invalid_format' })
 */
export function trackFormError(params: FormErrorParams): void {
  send('form_error', {
    event_category: 'form_interaction',
    form_id: params.form_id,
    field_name: params.field_name,
    error_type: params.error_type,
    error_message: params.error_message ?? '',
  })
}

// ── 4. Conversión final ──────────────────────────────────────────────────

export interface ConversionParams {
  method: 'email' | 'google' | 'whatsapp'
  plan?: 'free' | 'pyme_pro' | 'enterprise'
}

export function trackConversion(params: ConversionParams): void {
  send('sign_up', { // GA4 evento recomendado
    event_category: 'conversion',
    method: params.method,
    plan: params.plan ?? 'free',
    value: 1,
    currency: 'COP',
  })
}

// 03 — A/B Testing

useABTest — Hook con GA4

🧪
El Reto: Sin enviar la variante a GA4 como dimensión, es imposible segmentar las métricas del embudo por variante A vs B. Los datos de conversión aparecen mezclados e inútiles para tomar decisiones.

El hook asigna la variante de forma persistente (localStorage), la envía a GA4 como experiment_impression y la expone como dimensión personalizada en cada evento posterior.

src/hooks/useABTest.ts
import { useState, useEffect } from 'react'

/**
 * useABTest — Hook de A/B Testing con integración GA4
 *
 * - Asigna la variante 50/50 de forma aleatoria.
 * - Persiste la asignación en localStorage (misma variante en recargas).
 * - Dispara un único evento experiment_impression por sesión.
 * - Registra la variante como dimensión personalizada en GA4.
 *
 * @param experimentId  ID único del experimento (ej. 'hero_cta_v2')
 * @returns { variant: 'A' | 'B', isLoading: boolean }
 *
 * Configura en GA4:
 *   Admin → Custom Definitions → Custom Dimensions:
 *   Nombre: "Experiment Variant" | Scope: User | Parameter: experiment_variant
 */

declare const window: { gtag?: Function } & Window

type Variant = 'A' | 'B'

interface ABTestResult {
  variant: Variant | null
  isLoading: boolean
}

function getOrAssignVariant(experimentId: string): Variant {
  const key = `ab_${experimentId}`
  const stored = localStorage.getItem(key)

  if (stored === 'A' || stored === 'B') {
    return stored // Variante ya asignada → mantener consistencia
  }

  const assigned: Variant = Math.random() < 0.5 ? 'A' : 'B'
  localStorage.setItem(key, assigned)
  return assigned
}

function fireExperimentImpression(
  experimentId: string,
  variant: Variant
): void {
  if (typeof window === 'undefined' || !window.gtag) return

  // 1. Dispara el evento de impresión del experimento
  window.gtag('event', 'experiment_impression', {
    experiment_id: experimentId,
    experiment_variant: variant,
    event_category: 'ab_testing',
    non_interaction: true, // No distorsiona bounce rate
  })

  // 2. Registra la variante como User Property (dimensión de usuario)
  //    Permite segmentar TODO el embudo por variante en los reportes
  window.gtag('set', 'user_properties', {
    experiment_variant: `${experimentId}_${variant}`,
  })
}

export function useABTest(experimentId: string): ABTestResult {
  const [variant, setVariant] = useState<Variant | null>(null)
  const [isLoading, setIsLoading] = useState(true)

  useEffect(() => {
    // Client-only: evita hydration mismatch en SSR
    const assigned = getOrAssignVariant(experimentId)
    setVariant(assigned)
    setIsLoading(false)

    // Solo dispara si es primera vez que se asigna en esta sesión
    const impressionKey = `ab_impression_${experimentId}`
    if (!sessionStorage.getItem(impressionKey)) {
      fireExperimentImpression(experimentId, assigned)
      sessionStorage.setItem(impressionKey, '1')
    }
  }, [experimentId])

  return { variant, isLoading }
}

Así se usa el hook en tu componente:

src/components/HeroCTA.tsx — Ejemplo
import { useABTest } from '@/hooks/useABTest'
import { trackCTAClick } from '@/lib/analytics'

export function HeroCTA() {
  const { variant, isLoading } = useABTest('hero_cta_v2')

  // Evita flash de contenido incorrecto durante hidratación
  if (isLoading) return <CTASkeleton />

  const ctaText = variant === 'A'
    ? 'Probar FiscalAI Gratis'       // Control
    : 'Automatiza tus facturas hoy'  // Variante B

  return (
    <button
      onClick={() =>
        trackCTAClick({
          location: 'hero',
          label: ctaText,
          plan: 'free',
        })
      }
    >
      {ctaText}
    </button>
  )
}

// 05 — Deploy

Checklist de Lanzamiento

01

Variables de entorno

Agrega NEXT_PUBLIC_GA_ID o VITE_GA_ID en tu plataforma de deploy (Vercel / Netlify). Nunca hardcodees el Measurement ID.

02

Verificar en DebugView

En GA4 → Admin → DebugView, activa el modo debug con la extensión GA Debugger y verifica que cada evento llega con sus parámetros correctos.

03

Crear dimensiones personalizadas

Registra experiment_variant, cta_location y plan como Custom Dimensions en GA4 Admin para poder usarlas en reportes.

04

Marcar conversiones

En GA4 → Events, activa el toggle "Mark as conversion" para sign_up y cta_click. Así aparecen en los reportes de conversión.

05

Crear Funnel Exploration

En GA4 → Explore → Funnel Exploration, arma el embudo con los 5 eventos en orden. Activa "Closed funnel" para medir abandono exacto por paso.

06

Audience por variante A/B

Crea dos Audiences filtrando por experiment_variant = hero_cta_v2_A y _B. Aplícalas como comparación en el Funnel Exploration para ver tasas de conversión por variante.
